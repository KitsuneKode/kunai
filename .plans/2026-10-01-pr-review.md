## Standards

Six actionable findings on this axis. Rule sources: AGENTS' declaration→reader/every-platform seams, the analytics privacy contract and the changed release/metric contracts. Source links pin the reviewed implementation rather than a moving branch.

### ST1 — P1: a completed ping restores an identifier cleared by another window

Applies to #501 and #507. In [#501's sender](https://github.com/KitsuneKode/kunai/blob/a8adea285e727920b165da4acda9a13812a8b53c/apps/cli/src/services/analytics/usage-analytics-service.ts#L263) and [#507's sender](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/cli/src/services/analytics/usage-analytics-service.ts#L258), response completion checks stale instance state and dirties the original install ID/bookkeeping. The config save then merges those fields onto another window's disabled config.

**Reproduction:** hold A's injected POST; B disables and flushes; release A with 204. Both heads change disk from `analytics: disabled, hasInstallId: false` to `analytics: disabled, hasInstallId: true, hasPingBookkeeping: true`. No real request/profile was used. Existing pending-ping tests mutate the same instance. #501 refreshes before sending, but not at completion; #507's locked dirty-key merge does not condition identity writes on current consent. Those were the attempted disproofs.

**Fix/acceptance:** make analytics bookkeeping a conditional durable mutation under the same ownership boundary as config writes. Require still-enabled consent and the same original identity; otherwise write nothing. Test second-window disable and rotation while success, 400, 503 and transport failure are held. A refresh followed by an unconditional write still has a race. Owner: R05, with R07 privacy signoff.

### ST2 — P1: the PowerShell bootstrap does not enforce the new signing policy

[#507's install.ps1](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/install.ps1#L2154) downloads hashes and the executable but never requests a manifest signature. Unix and TypeScript paths add signature enforcement; the independent Windows bootstrap does not inherit them.

**Reproduction:** run real PowerShell installer function bodies with only the download boundary replaced: archive manifest unavailable, matching unsigned raw manifest/payload, signatures unavailable. Installation succeeds: `installed: true, requestedSignature: false`. Fixture bytes were never executed; profile/PATH mutations were isolated/disabled. Searching the complete bootstrap found no signature handling. This is inherited checksum-only behavior left uncovered by #507's new release promise, not a claim that the old PowerShell path enforced signatures.

**Fix/acceptance:** verify both manifest forms against the pinned Ed25519 key before trusting hashes. Missing/invalid/foreign signatures must fail without entering unsigned compatibility fallback. Use real pwsh tests and hosted Windows initial-install/upgrade qualification. Owner: release/native-installer seam coordinated with R07.

### ST3 — P1: AniDB bypasses a disabled direct-fallback policy

[#507's AniDB metadata fallback](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/packages/providers/src/anidb/client.ts#L358) catches a relay refusal and opens direct global fetch. The relay port itself correctly throws when `fallbackToDirect: false`; its provider caller defeats that policy.

**Reproduction:** compose the real relay port/registry and provider adapter with external boundaries stubbed. A relay-generated `unknown-provider` refusal produces both a relay RPC and a direct AniDB request, returning direct success despite fallback false. The request signal is not aborted. #502's shared refusal type and provider propagation are the attempted disproof and the implementation to preserve; #507 defines a separate private error contract.

**Fix/acceptance:** retain one shared refusal contract and propagate it through every adapter/fallback. Compose real port + adapter tests for fallback on/off, explicit relay refusal and ordinary upstream responses. Owner: R01/#502 integration.

### ST4 — P1: stale config-lock reclamation can erase a live replacement lock

[#507's FileStorage](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/cli/src/infra/storage/FileStorage.ts#L255) checks stale ownership, then unconditionally unlinks. Release also unconditionally removes the path. Public `mutate()` reaches this protocol.

**Reproduction:** two actual storage instances read the same dead-owner lock. A reclaims/acquires and pauses inside its critical section. B finishes its older stale check, deletes A's live lock and commits. A resumes and overwrites B's key. Actual isolated disk ends `{initial: true, first: true}`, losing `second: true`. Controlled promises schedule reads; no sleeps or real profile. `O_EXCL` protects creation, not stale removal; object-local serialization cannot protect separate instances/processes.

**Fix/acceptance:** use a reviewed ownership-safe acquisition/recovery/release protocol, or fail conservatively until explicit recovery. Use unique ownership identity and protect initializing owners; a check followed by unlink is insufficient. Test two stale contenders, a new live replacement, late release and no lost updates. Owner: R05; reconcile the separate #501 save/refresh implementation.

### ST5 — P2: retirement/return changes historical lifetime counts

[#507's insert/unretire SQL](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/analytics-ingest/src/postgres-store.ts#L36) and [retirement schema](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/analytics-ingest/sql/003_retired_install.sql#L8) retain a hash without original `first_seen`. Return inserts a new first-seen date. Retired counts also lack an as-of-day predicate.

**Reproduction:** first ping Jan 1 → Jan 2 lifetime 1; prune Jan 3 → Jan 2 lifetime 1; same identity returns Mar 1 → recomputed Jan 2 lifetime 0, current lifetime 1. This ran against the real memory store; matching SQL was inspected, not executed against Postgres. Current-day returning-install tests do not cover chronology.

**Fix/acceptance:** retain/recover original first-seen through retirement, apply historical boundaries, and test retire→return→recompute against memory and disposable Postgres. Explain unrecoverable pre-migration chronology honestly; confirm permanent deduplication retention and its disclosure before rollout. Owner: R07.

### ST6 — integration blocker: cleanup callers do not consume retained deletion results

[#504's helper](https://github.com/KitsuneKode/kunai/blob/3a46430226e34feb3ec88b9d021430bca533d2e8/apps/cli/src/services/download/download-cleanup-candidates.ts#L212) accepts `Promise<void>` and records every fulfilled call as deleted. #507 changes the service to `Promise<DownloadDeleteResult>`, including resolved `retained` failures. The concrete service cannot satisfy that old parameter type. This is inspected interface/caller evidence, not an executed combined-tree typecheck.

**Fix/acceptance:** update every deletion entrypoint to branch on the discriminant; retain retry ownership and report retained files. Changing only the type annotation would still falsely report deletion. Add real retained-file + cleanup-banner/freed-byte tests. Owner: R03/R08 and #504 integration. SP5 below describes the existing public behavior separately.

Standalone #500 context: its AniDB HLS wrapper drops `RequestInit.redirect`/headers. A injected-port reproduction modeling automatic redirects reaches `169.254.169.254` and returns an auto candidate. No real private endpoint was requested. #507 repairs this exact wrapper and adds a regression. Preserve/backport that narrow repair; do not report it as an unfixed #507 issue.

### SP2 — P1: an initializing Android session lock can be stolen

R06 requires concurrent writes to be serialized or rejected. [#507's session acquisition](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/mobile/src/runtime/android/node-session.ts#L38) treats a missing/unreadable PID as stale, deleting a lock another process may have just created. Release at line 59 also lacks ownership checking.

**Reproduction:** inject a second acquire between the first `mkdir(lock)` and PID write; both return release functions. Real temporary filesystem, only scheduling boundary controlled; expected exclusion test fails. PID liveness and existing steady-state stale-lock tests do not protect this initialization window.

**Fix/acceptance:** publish ownership atomically, conservatively handle incomplete owners, and release only current ownership. Test simultaneous acquisition, stale recovery and delayed releases before physical qualification. Owner: R06. ST4 is a separate desktop config-lock protocol with a similar failure pattern.

### SP3 — P1: account replacement is not transactional on token-store failure

R05.1 says persist validated credentials before publishing adapter state, preserving prior state on failure. [#507's AniList adapter](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/cli/src/services/sync/AniListAdapter.ts#L346) sets candidate state before validation/storage. Public connect reaches it at line 331. Validation failure restores state; durable commit failure does not. The connect signal is also omitted from validation.

**Reproduction:** load old token/account, validate new Viewer, reject `patchAniList` with disk-full. Subsequent public identity refresh sends `Bearer new-token` although durable credentials remain old. Existing auth tests do not cover this storage failure.

**Fix/acceptance:** validate in local candidate state, forward cancellation, commit the record, then publish. Rejected/aborted/failed-store replacements must preserve old state and isolate its queued work. Test the complete connect lifecycle and account switching, not only successful Viewer responses. Owner: R05.

### SP4 — P1: an already-saved external opt-out does not prevent #507 from sending

The privacy contract/runbook require user-controlled delivery. [#507's pre-send path](https://github.com/KitsuneKode/kunai/blob/d205805262218ec7ca9bef18bc18fab6ae029d81/apps/cli/src/services/analytics/usage-analytics-service.ts#L222) reads stale memory. The dirty-key merge protects unrelated writes but never refreshes consent before the network action.

**Reproduction:** two real ConfigService instances share an in-memory disk; B saves disabled/empty ID before A calls `maybePing`. A's injected fetch is called once, expected zero. #501's pre-send refresh solves this ordered case, but is absent from #507. This is distinct from ST1's opt-out during an already-running ping.

**Fix/acceptance:** preserve #501's fresh-consent read in the reconciled implementation and ST1's conditional durable completion. Test both ordered opt-out and opt-out while a response is held. Owner: R05/R07.

### SP5 — P2: the new cleanup review announces space that was not freed

#504 promises named per-item outcomes and freed-byte feedback. Its helper counts every fulfilled deletion, and [its UI](https://github.com/KitsuneKode/kunai/blob/3a46430226e34feb3ec88b9d021430bca533d2e8/apps/cli/src/app-shell/workflows/download-cleanup-review.ts#L77) sums those stored sizes. Inherited DownloadService swallows removal errors, deletes the ownership record and resolves. EACCES/EBUSY/EIO can therefore leave media on disk while the new review reports freed bytes.

**Evidence/disproof:** read the production deletion callee and tests; tests use a rejected mock, unlike the resolving production failure. The underlying A04 removal-error mechanism was reproduced in the earlier audit. No new native #504 error-injection run was performed, so this is confirmed caller/callee reachability of known A04, not a newly reproduced filesystem defect.

**Fix/acceptance:** integrate truthful retained results, count successful physical deletion only and preserve retry ownership. Revalidate current eligibility/protection after confirmation and before each deletion; bulk review currently consumes the old array and returns, despite the body saying it re-lists. Restrict revalidation to originally confirmed IDs. Owner: R03/R08; coordinate ST6.
