## Phone direction without operating a hosted website

First qualify the prepared Termux+VLC and a-Shell+VLC kit on both physical phones: launch, cancellation, header-sensitive provider request, player handoff, return and offline durability. Record actual observations; neither phone is qualified yet. The zip is a test bundle, not a store installer.

The best next user-facing experiment is **a single Kunai process serving bundled touch UI and a local API**, with one queue/history owner. Start with Queue, Downloads, Now Playing and post-play actions. Offer both Play here (phone/player handoff) and Play on host. Pair/revoke access explicitly; do not expose an unauthenticated LAN server. A desktop tray/launcher shortcut plus QR pairing can hide terminal setup for nontechnical users. No permanently operated website is required.

LAN access needs device-trusted HTTPS or an explicitly user-owned secure tunnel before exposing paired control/state. Service-worker installation requires a secure context; the localhost exception on the desktop does not make its LAN IP secure on a phone. [MDN service-worker requirements](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers) support this boundary. Avoid promising a nontechnical “installable offline app” from a plain LAN URL.

A smaller, useful computer-off phone slice is **transfer completed downloads into existing VLC**, before building a new phone runtime. VLC documents [iPhone USB/Wi-Fi media synchronization](https://docs.videolan.me/vlc-user/desktop/3.0/en/gettingstarted/mobileoverview/ios/media_synchronization.html) and [Android local media folders](https://docs.videolan.me/vlc-user/android/3.5/en/more/settings/general_settings.html). An eventual Kunai export action can validate selected completed jobs, preserve episode names/sidecars and prepare a transfer manifest. Qualify actual import, subtitles, order, storage permission and offline reopen on both phones; playlist interoperability and automatic progress return are not assumed. This is a proposed slice, not an implemented export feature. It gives phone-local playback; Kunai catalog search and new acquisition still need their own runtime.

This companion depends on its host staying on. Browser installation/offline UI caching does not make the runtime or provider acquisition run on a computer-off iPhone. Android phone-local hosting in Termux may be another bounded experiment, still requiring device/runtime qualification. Standalone iPhone support needs a separate execution/runtime and packaging decision. TanStack Router+Query is sufficient for a lean static client; Start SPA mode can fit if its additional machinery serves an actual need. Keep the versioned local API usable by a future native UI rather than coupling core policy to one web framework.
