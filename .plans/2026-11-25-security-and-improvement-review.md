# Kunai security and improvement review

Reviewed `origin/main` at `879b668f44cb4b6352d974703d047c4c8478293a` on 2026-11-25. The review covered the production provider registry and representative network-to-sink paths, Stremio, desktop mpv, the native installers and update path, CI and package channels, credential stores and tracker authorization, analytics, the hosted relay adapter, both mobile runtime adapters, and the docs site.

Verification used the pinned source, existing automated tests and harmless local fixtures. The baseline suites ran on `0c889e352`. The two subsequent main commits changed VHS fixtures, documentation and a type comment. The affected consent and VHS suites ran again on the reviewed revision, with 44 passing and no failures. Runtime checks used a disposable home, unset XDG and APPDATA overrides, and `DO_NOT_TRACK=1`. The review did not use production analytics or relay services. Hosted enforcement and deployment, native Windows ACLs and named-pipe access, macOS Keychain, and physical handoff remain unverified.

## Security findings

### Critical and high

No finding met these severity thresholds on the evidence available. The release signing enrollment gate is recorded below because it determines which artifacts actually enforce signatures.

### Medium

#### M1. Bundled provider subtitles bypass guarded fetching on desktop

- **Reachability.** Videasy keeps HTTP(S) subtitle URLs from the provider response in [direct.ts](../packages/providers/src/videasy/direct.ts#L2254). The [provider result adapter](../apps/cli/src/services/providers/provider-result-adapter.ts#L121) only marks Stremio tracks for guarded handling. The startup path passes ordinary URLs to mpv through [mpv.ts](../apps/cli/src/mpv.ts#L818). Persistent attachment passes the resolved value to `sub-add` in [persistent-subtitle-manager.ts](../apps/cli/src/infra/player/persistent-subtitle-manager.ts#L174). The [subtitle resolver](../apps/cli/src/infra/player/addon-subtitle-files.ts#L238) and [remote URL predicate](../apps/cli/src/infra/player/mpv-playback-url.ts#L4) leave the connection to mpv and check only the scheme.
- **Impact.** A bundled provider or upstream subtitle source that controls a returned URL can cause playback to initiate an HTTP request from the viewer's machine to a local service. A supported subtitle format is needed to show its contents. Request side effects can occur before format validation. This applies when a remote subtitle is attached.
- **Verification.** A benign fixture produced an unchanged public subtitle URL in startup arguments and in the late resolver. Existing [mpv safety tests](../apps/cli/test/unit/infra/player/mpv-args-safety.test.ts#L212) reject local file schemes. The download [sidecar path](../apps/cli/src/services/download/DownloadService.ts#L2159) and Stremio localization have separate guarded transports and do not protect this desktop path. No request to a private service was made. The [boundary and downloads plan](./boundary-hardening-and-adaptive-downloads.md) owns related refactoring but does not specify this network invariant.
- **Fix.** Route externally sourced tracks from every adapter through a bounded, cancellable download that pins checked addresses and rechecks redirects. Pass an owned local file to mpv. Keep explicit local-library tracks under their existing authority and preserve origin-scoped headers where needed.

#### M2. The Stremio media probe and mpv use separate connections

- **Reachability.** The [bootstrap](../apps/cli/src/container/bootstrap-providers.ts#L255) requires experimental consent and an installed addon. The [strict preflight](../apps/cli/src/services/playback/stream-health-check.ts#L64) verifies a bounded direct-media response through a DNS-pinned request. The [one-shot launcher](../apps/cli/src/mpv.ts#L946) and [persistent launcher](../apps/cli/src/infra/player/PersistentMpvSession.ts#L775) still hand the original hostname to mpv. The [persistent replacement](../apps/cli/src/infra/player/PersistentMpvSession.ts#L520) also uses the original stream address after its check.
- **Impact.** An installed addon can select an attacker-controlled media hostname. A subsequent player connection can resolve or answer differently from the guarded probe and reach a viewer-local HTTP service under suitable DNS and player conditions. The threat requires addon opt-in and playback. The tested probe and documented mpv options narrow the exposure. They do not make the two connections share a vetted endpoint.
- **Verification.** Traced the address pin in [stream-target-guard.ts](../packages/core/src/stream-target-guard.ts#L220), the separate spawn and replacement paths, and the player option tests. The [Stremio feature contract](../.docs/features/stremio-addons.md#L81) already records this residual and the version-dependent redirect limitation. No rebinding or private-network traffic was exercised. [Provider platform](./2026-11-23-provider-platform.md) owns the addon track.
- **Fix.** Keep the experimental gate until the player can consume the same confined request policy. Evaluate a session-scoped, device-local transport that pins every outbound destination, refuses unexpected redirects and media responses, and preserves TLS hostname checks. Keep the deployed metadata relay outside the media path.

#### M3. The analytics admission limit does not cap database work

- **Reachability.** The public [ping handler](../apps/analytics-ingest/api/ping.ts#L84) admits a bounded schema-valid POST without authentication. [Ingest](../apps/analytics-ingest/src/ingest.ts#L121) HMACs the client-supplied identity and invokes `recordPing`. [The SQL](../apps/analytics-ingest/src/postgres-store.ts#L25) updates a single day row before checking the ceiling. The same update still runs for an over-budget request.
- **Impact.** A sender can consume the shared budget while generating few distinct installs. Other installs then get the same `204` as an admitted request and their data goes unrecorded. Continued valid requests still generate database traffic and contend on that row. The ceiling limits ping and lifetime rows. It leaves function invocations and the budget update exposed to traffic reaching the application.
- **Verification.** Read the HTTP, ingest, memory-store, and SQL paths. The [Postgres tests](../apps/analytics-ingest/test/postgres-hardening.test.ts#L47) explicitly cover budget exhaustion and duplicate charging. The isolated run exercised memory and SQL-shape tests. Database-backed tests skipped without a fixture database. The [analytics redesign](./usage-analytics-redesign.md) already calls for external rate and cost controls. Their deployed settings were outside this review.
- **Fix.** Apply the documented rate control before the function, avoid mutating the budget row once the ceiling is reached, and account for duplicate identities separately from admission where practical. Measure dropped valid pings and budget contention with a disposable database. Keep client IPs out of the application.

#### M4. An older upgrade can overwrite a newer activation

- **Reachability.** The [background updater](../apps/cli/src/services/update/BinaryAutoUpdater.ts#L93) compares latest against its running version and starts the download. [Explicit upgrade](../apps/cli/src/services/update/run-upgrade.ts#L81) makes its decision before calling the installer. The native installer re-reads the manifest under the [cross-version activation lock](../apps/cli/src/services/update/native-installer/install-latest.ts#L314) and checks ownership, then publishes the resolved version without comparing it to the active version under that lock.
- **Impact.** An earlier update that finishes after a newer install can move the launcher and manifest back to an older authentic version. Stale release discovery or ordinary overlapping updates can produce the ordering. This can reverse a security upgrade even with a correct signing key. Explicitly requested installs and rollback are intentional ways to select an older version.
- **Verification.** Followed latest discovery, the process-version checks, per-version staging, locked publication and manifest ownership checks. Version-bound signature tests reject a signature for the wrong release, which leaves this ordering possible with two distinct valid releases. Review is source-based. The local signed-installer tests did not schedule this overlap. The distribution workstream in the [9.5 plan](./2026-11-24-road-to-9-5.md) owns related lifecycle work.
- **Fix.** Carry install intent into the locked publication. For upgrades, compare the resolved version against the latest active manifest and decline stale activation while leaving deliberate rollback available. Add a deterministic two-version publication-order test.

#### M5. Main CI executes an unpinned external test executable

- **Reachability.** The main-push and PR test job downloads the moving yt-dlp `latest` asset and invokes it in [ci.yml](../.github/workflows/ci.yml#L261). The [workflow environment](../.github/workflows/ci.yml#L15) supplies the remote-cache token when configured and the workflow has a read-only repository token.
- **Impact.** A party able to replace the third-party executable delivered to the runner can execute code in the verification job before tests run, alter its evidence or access credentials available to that job. The protected publication job is separate. This finding does not establish access to release credentials or poisoning of published binaries.
- **Verification.** Read the whole install step and following test steps, and compared the job token scope with the separate [release publication job](../.github/workflows/release.yml#L1005). The step does execute the asset despite the description of the tests' dependency. No download or hosted test was initiated. The [CI maturity plan](./2026-09-12-test-ci-audit.md) owns CI improvements.
- **Fix.** Replace the binary with a checked-in presence fixture if tests only use `Bun.which`. If execution is needed, use a reviewed pinned asset and digest, store it in a runner-owned directory, and keep remote-cache credentials out of jobs that can run without them.

### Low

#### L1. First-launch media credentials remain in mpv process arguments

- **Reachability.** [The sensitive options collector](../apps/cli/src/mpv.ts#L639) protects extra headers and yt-dlp options with a private include file. [The argument builder](../apps/cli/src/mpv.ts#L946) still emits the original media URL for one-shot and initial persistent launches. The same builder emits the dedicated referrer as an ordinary argument at [mpv.ts](../apps/cli/src/mpv.ts#L794). [Persistent startup](../apps/cli/src/infra/player/PersistentMpvSession.ts#L873) launches that argument vector.
- **Impact.** On hosts where another local process can inspect arguments, it can read a signed media locator, or a referrer carrying a capability, while the player is running. What it can reuse depends on expiry, IP binding and upstream policy. This is about media request credentials. The OS vault OAuth tokens are a separate data path.
- **Verification.** The local argument fixture retained a benign signed-query placeholder verbatim. Existing [mpv argument tests](../apps/cli/test/unit/infra/player/mpv-args-safety.test.ts#L74) verify include-file handling and do not assert URL confidentiality. The later IPC load path does not put each replacement on process arguments. No process owned by another user was inspected.
- **Fix.** Start managed mpv idle and load even the first remote item over a verified private IPC channel. Give any remaining one-shot path an owner-only input mechanism and test the full argument surface, including signed locators and referrers.

#### L2. Provider matrix puts operator input into shell source

- **Reachability.** The [provider matrix workflow](../.github/workflows/provider-matrix.yml#L9) is limited to manual dispatch and schedule. Its [matrix step](../.github/workflows/provider-matrix.yml#L60) substitutes the free-text provider selection directly into a shell assignment. Validation by the CLI would run after shell parsing.
- **Impact.** A person able to dispatch the workflow with a manipulated selection can make the runner interpret that input as shell syntax or alter the resulting matrix evidence. The job has read-only repository permissions and no configured release credentials in the workflow. The input is unavailable to a fork PR author through the normal PR event, which limits severity.
- **Verification.** Traced triggers, modes, job permissions and artifact destinations. Compared the [package-channel tag handling](../.github/workflows/package-channels.yml#L30), which passes its input through the environment and validates it before use. No crafted workflow was dispatched.
- **Fix.** Pass the selection as an environment value, validate tokens against known IDs or lanes, and call the CLI with an array of quoted arguments.

## Ruled out

- **Stremio manifest redirect to a local file or private literal.** The [addon request](../packages/providers/src/stremio-addon/client.ts#L86) requires HTTPS on every hop and uses the [guarded DNS transport](../packages/core/src/stream-target-guard.ts#L207).
- **Stremio CR/LF or framing header injection.** The [addon classifier](../packages/providers/src/stremio-addon/streams.ts#L80) refuses controls and reserved transport headers, and [mpv normalization](../apps/cli/src/infra/player/mpv-stream-http-headers.ts#L125) handles header list separators.
- **Generic option injection into mpv by a stream URL or title.** [The builder](../apps/cli/src/mpv.ts#L762) gates media schemes, keeps titles in one option value and uses separate process arguments. IPC sends structured commands. [Script options](../apps/cli/src/infra/player/kunai-mpv-bridge.ts#L82) come from local configuration, and [IPC paths](../apps/cli/src/infra/player/mpv-ipc-endpoint.ts#L197) are generated by Kunai. The [bundled Lua bridge](../apps/cli/assets/mpv/kunai-bridge.lua#L1033) uses fixed player commands on the reviewed paths.
- **A normal Unix mpv socket is directly exposed in shared temp.** [Directory verification](../apps/cli/src/infra/player/mpv-ipc-endpoint.ts#L78) rejects non-private, foreign-owned and symlink final directories. The native Linux endpoint tests cover the actual socket path. Windows pipe names and Unix permissions are different boundaries. The Windows pipe DACL needs native verification.
- **Download or subtitle names take arbitrary parts from a network path.** [Download naming](../apps/cli/src/services/download/download-path-naming.ts#L94) sanitizes title and year per component. [Subtitle naming](../apps/cli/src/services/download/subtitle-artifact-path.ts#L15) keeps only a recognized extension and derives the destination from the video path. Addon subtitle files use [owned numbered paths](../apps/cli/src/infra/player/addon-subtitle-files.ts#L97).
- **Simple terminal escape strings execute through the inspected Ink title and picker paths.** The [display boundary](../apps/cli/src/domain/text-display.ts#L10) strips CSI, OSC, remaining control bytes and bidi format controls before measuring or truncating. Existing tests cover the sanitizer. This check covered the sampled display paths.
- **Network JSON automatically pollutes global prototypes.** Parsing JSON itself produces data. The [versioned provider manifest parser](../packages/providers/src/shared/manifest-bundle.ts#L55) rejects prototype-related keys, and the reviewed Stremio and analytics parsers select known fields. No path from the sampled network inputs to a global prototype mutation was established.
- **Personal TMDB keys ride the catalog fallback or tracker calls use a mirror.** The [catalog mirror definitions](../apps/cli/src/services/catalog/tmdb-proxy.ts#L148) are keyless and the [catalog fetcher](../apps/cli/src/services/catalog/tmdb-proxy.ts#L397) attaches credentials only to direct hosts. The [tracker adapter](../apps/cli/src/services/sync/TmdbAdapter.ts#L187) uses direct TMDB endpoints. The fallback still receives catalog query metadata as documented.
- **The ordinary debug sink writes known auth fields verbatim.** [Logger wiring](../apps/cli/src/container/bootstrap-persistence.ts#L205) applies [credential and URL redaction](../apps/cli/src/services/diagnostics/redaction.ts#L26) before file and console output. Redaction tests cover known fields and signed query parameters. Arbitrary provider prose remains a heuristic case. mpv’s separately requested native log uses its own sink.
- **An arbitrary web origin can complete AniList OAuth.** The [callback validator](../apps/cli/src/services/sync/auth-contract.ts#L106) requires a registered loopback shape. The [collector](../apps/cli/src/services/sync/oauth-loopback.ts#L79) checks origin, POST, fetch-site when present, a per-attempt collector path, and state before accepting a successful callback.
- **The current vault backends put tracker tokens on argv.** [Credential writes](../apps/cli/src/services/persistence/credential-vault-backends.ts#L83) use stdin for the OS helpers. Config and file fallback create owner-only files on POSIX via [atomic-write.ts](../apps/cli/src/infra/fs/atomic-write.ts#L161). On Windows the write inherits the parent ACL initially and tightening is best effort. The audit did not establish exposure under the default Windows profile ACL.
- **Pinned installers fall back to unsigned artifacts when a signature is absent.** The [native verifier](../apps/cli/src/services/update/native-installer/install-latest.ts#L154) requires the signature when keyed. Local signed-installer tests reject missing, altered and wrong-version signatures for Bash and PowerShell. Archive compatibility falls back to the independently authenticated raw manifest in pinned builds.
- **A malformed release archive can choose the installed pathname.** The [native archive reader](../apps/cli/src/services/update/native-installer/release-archive.ts#L95) checks the archive’s structure and expected payload entry before staging. Bash and PowerShell validate the expected entry before activation. Predictable staging names rely on the user-owned cache root. A cross-user write into the default root was not established.
- **An untrusted PR event can invoke protected release publication.** The workflow inventory has no `pull_request_target` or `workflow_run` promotion. [Protected publication](../.github/workflows/release.yml#L1005) uses a separate job, exact candidate artifacts, a current-main check and provenance verification. Hosted rules, cache service settings and release environment protections were outside the run.
- **Skipping setup or starting noninteractively permits an analytics send.** [Consent handling](../apps/cli/src/services/analytics/usage-analytics-service.ts#L186) and [delivery policy](../apps/cli/src/domain/analytics/consent-policy.ts#L38) require consent and interactivity, and `DO_NOT_TRACK` or `CI` blocks sending. Setup keystroke and Settings persistence tests passed. The send checks persisted consent and the same install identity again before posting. The [ingest runtime](../apps/analytics-ingest/src/runtime-config.ts#L43) refuses a missing HMAC secret.
- **Public analytics expose raw IDs, client IPs, or a joint user breakdown.** [Ingest](../apps/analytics-ingest/src/ingest.ts#L121) stores a keyed pseudonym and [public metrics](../apps/analytics-ingest/src/public-metrics.ts#L69) publish marginal buckets with suppression and an elimination guard. Exact daily totals and differing series windows remain inference surfaces when a viewer has auxiliary information. No individual identity recovery was established.
- **The hosted relay accepts arbitrary destinations or exposes a media route.** [The hosted adapter](../apps/relay-server/src/api/rpc/%5BproviderId%5D.ts#L55) requires bearer auth before reading a request body. The [shared handler](../packages/relay/src/handler.ts#L113) enforces registered metadata hosts on each hop and [pins validated DNS](../packages/relay/src/pinned-transport.ts#L99). There is no media route in [relay-app.ts](../apps/relay-server/src/relay-app.ts#L16). An authenticated caller can select paths and ports on allowed hosts, within response caps. No reachable provider media path through those hosts was established. Request volume protection depends on the deployment.
- **An Android URL becomes a shell command.** The [mobile URL parser](../apps/mobile/src/application/portable-url.ts#L8) requires credential-free HTTPS and the [Android adapter](../apps/mobile/src/runtime/android/android-player-port.ts#L42) spawns with a fixed argument layout and `shell: false`. The desktop Termux [intent launcher](../apps/cli/src/infra/player/android-intent-launcher.ts#L59) also supplies argv. The external `am` and `termux-am` binaries own downstream `app_process` behavior. The [a-Shell helper](../apps/mobile/scripts/ashell/kunai-mobile-open-vlc) quotes its generated VLC URL.
- **Untrusted docs request input is compiled as MDX or breaks JSON-LD out of its script.** [MDX configuration](../apps/docs/source.config.ts#L14) compiles checked-in files. [JSON-LD serialization](../apps/docs/lib/json-ld.ts#L8) escapes `<`, release markdown uses [React Markdown](../apps/docs/components/shared/markdown-text.tsx#L76) without raw HTML, and remote chart labels are [encoded before use as CSS keys](../apps/docs/components/analytics/share-over-time.tsx#L73). GitHub tokens are read by [server-side helpers](../apps/docs/lib/github-stars.ts#L19) that return public metadata. No token value is passed to the client in the reviewed callers.

### Release enrollment still required

The checkout's [release key pin](../apps/cli/src/services/update/release-key.json#L1) is empty and [v0.4.0](../.release/kunai-v0.4.0.json#L3) is staged. Local docs generation emitted both branded installer scripts with an empty pin. This is the deliberate [pre-publication renderer branch](../scripts/packaging/render-installers.ts#L19). Source builds likewise get the empty pin through [build-shared.ts](../apps/cli/scripts/build-shared.ts#L98). A party able to replace both payload and manifest on a trusted download channel could defeat checksum-only verification for these artifacts. This is an existing trust dependency of the unsigned channel, with enrollment already owned by W4. Qualify the key in candidate binaries, the protected publication output and the installer served by the branded build before claiming authenticated distribution. A successful fixture with an embedded test key does not attest those deployed bytes.
