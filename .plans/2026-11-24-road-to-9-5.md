## What six advisers agree on (2026-11-24)

Opus 5.5, Fable 5.2, Sol 6.2, Astra 6.2, Grok 4.7 (xhigh) and Gemini 4 Neon
each audited `main` for "how to reach 9.5 the right way" and what to prune.
Where at least four agree, it is listed here. Claims were spot-checked
against the tree before they were acted on, and two were refuted.
`prototype:serve` runs a gitignored local harness, so it is not dead.
`imdb:` ids are rejected on purpose.

**The diagnosis is unanimous.** Kunai is not short of engineering. It is
short of releases. There are 912 commits since v0.3.0, and the release gate
waits on third-party sites being up. Every reviewer put "ship v0.4.0, then a
fixed train" first.

### Rules so it does not drift back

1. **Release on a date.** Tag every other week if the deterministic gate is green.
2. **Only what the project controls blocks a release.** Upstream site health feeds demotion and the notes.
3. **Rules become ratchets.** File size, in-flight maps, test sleeps (W6), anti-slop baseline, plan freshness. A rule without a test decays.
4. **Docs that list shipped behaviour are generated.** That covers provider order, flags and env vars.
5. **One class of finding per PR.** Each finding gets a failing test first. No 9k-line residue PRs.
6. **Retire in one PR.** Removing a provider updates the loader, migration list, barrel, user page and agent table together.

### Beyond the competitors (the bets reviewers converged on)

1. **Failover mid-stream at the same timestamp.** Watch mpv cache stalls over IPC, resolve the next source through `verifyCandidateStream`, then `loadfile … start=<pos>` keeping the subtitle and audio tracks. Proposed by Opus, Neon, Astra and Sol. One-shot launchers cannot do this.
2. **Replayable failure receipts.** A redacted resolve trace the user can inspect, which `kunai replay` turns into a fixture test. Proposed by all six.
3. **Health the client actually uses.** The sweep publishes a signed status on the release channel. The picker ranks and badges sources and skips dead ones, with no telemetry.
4. **Headless `kunai resolve`/`play --json`** behind the same probe gate, for scripts, rofi and agents.
5. **Offline runway.** Keep the next N episodes of followed shows on disk within a storage budget, verified playable.

### Still worth borrowing, in order

1. **Decoded-video readiness.** Observe mpv `video-out-params` (frame size from
   the decoder) and treat clock movement without it as unverified; raise a
   stall when frames stop after they started. Prerequisite for bet 1
   (mid-stream failover). Verify `--vo=null` behaviour on all three OSes first;
   drop the fork's `mpv-version` heuristic, which exists only for its owner's
   player shim.
2. **Recovery v2, on top of #751:** step a failing 4K rung down to 1080p on the
   same CDN before abandoning the source; adaptive startup stall (≈15 s with no
   bytes, 45 s while the cache fills); carry the user's audio and subtitle
   choice across failover; skip same-URL reconnect on `loading_failed` and
   codec errors. Port the fork's real-mpv recovery test
   (`stream-recovery-native.test.ts`, ffmpeg-generated media) with an injected
   clock.
3. **Early-window HLS probe** (fragments beyond the first; a CDN that 403s at
   segment 7). Only inside `verifyCandidateStream`, sampling 2–3 segments, for
   `quality-first` only — not as a provider-local check.
4. **`height`/`bitrate` on `StreamCandidate`** and quality-first selection across
   providers, after W1 settles `packages/types`.
5. **Legitimate sources:** Internet Archive as a gated provider; play a pasted
   URL through yt-dlp with the SSRF guard; "personal sources" (your own direct
   URL attached to a catalog id) stored under `getKunaiPaths()`. These belong to
   the platform plan's first-class-sources list and to W5.

### Demand signal

Two of five forks edited the core to add their own sources (this one with an
unsigned plugin directory, `sleepy090/kunai` with Russian sources in
`bootstrap-providers.ts`). That is evidence for platform Phase 2 (packs) and
W5 (addons) — not for adopting the fork's loader, which runs unsigned code in
process and does not enforce `verifyCandidateStream` on external modules.

### Phone: sequencing decided

The fork ships a Kotlin/Compose + Media3 Android app (phone and TV). Media3
takes request headers natively, which is the problem the loopback gateway
solves for VLC intents. Not taken as a codebase: it re-implements two
resolvers in Kotlin, carries its owner's private data, and uses the
`dev.kitsunekode.kunai` application id.

Order: finish the Android stream gateway (#629) → physical-device qualification
(#631) → `kunai serve` (M3 in
[mobile parity](./2026-10-11-mobile-parity-and-phone-web.md)) → only then a
one-day device spike on whether an APK can run the Bun binary (exec from
`nativeLibraryDir`, DNS and CA certificates outside Termux, 16 KB pages, RAM).
If the spike passes, a thin native shell talks to the same `kunai serve` API;
providers are never ported to Kotlin. 32-bit Android TV devices stay
unsupported (no 32-bit Bun).

### Not taken

The unsigned plugin loader; the owner's "Showtime" player shim and install
scripts; the fork's exclusion of `skipped` sources from failover (they are
untried, not dead).
