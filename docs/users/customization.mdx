Kunai stores preferences locally. Most settings are editable from `/settings` or `/setup` inside the shell. Advanced users can edit JSON directly.

`/settings` is organized into five sections:

| Section | What lives there |
| --- | --- |
| **General** | Startup mode, footer hints, theme, Mascot & tips, shortcut tips (with **Reset tips**), language/subtitle profiles, and Discover |
| **Sources** | Default providers, fallback priority, provider switches, Videasy session token, user-owned provider relay, and YouTube metadata/cookies/SponsorBlock |
| **Playback & Offline** | Recovery mode, startup priority, confirm-before-play, autoplay/skip controls, offline downloads, cleanup, and download path |
| **Accounts & Sync** | AniList & TMDB tracker sync and pause controls, plus local Discord Rich Presence |
| **Privacy & System** | Usage analytics opt-in/id rotation, update checks, **Advanced → Memory panel**, setup restore, and Danger Zone resets |

<Callout type="info" title="Config locations">
| File | Purpose |
| --- | --- |
| `~/.config/kunai/config.json` | User preferences, provider priority, language profiles, presence, downloads |
| `~/.config/kunai/install.json` | Install channel metadata (binary / npm / bun) |
</Callout>

## config.json

The main config file is created on first run or after `kunai --setup`. Kunai merges saved values with defaults on load, so you do not need every key present.

### Mode and providers

| Key | What it controls |
| --- | --- |
| `defaultMode` | Startup catalog: `series` (default), `anime`, or `youtube` |
| `provider` | Default movie/series provider for new sessions |
| `animeProvider` | Default anime provider |
| `providerPriority` | Fallback order for movie/series providers (empty = registry default) |
| `animeProviderPriority` | Fallback order for anime providers |
| `titleProviderPreferences` | Per-title provider override chosen explicitly by the user |
| `youtubeProvider` | Default YouTube-mode provider (default `youtube`) |
| `youtubeProviderPriority` | Fallback order for YouTube-mode providers (default `["youtube"]`) |

Unknown provider ids in priority arrays are ignored. Providers not listed remain available after configured entries.

More on fallback behavior: [Providers](/docs/users/providers).

### YouTube metadata and cookies

```json
{
  "youtubeMetadata": {
    "cookiesFromBrowser": "firefox",
    "cookiesFile": "/absolute/path/to/cookies.txt"
  }
}
```

- `cookiesFromBrowser`: optional browser profile name for yt-dlp (no default).
- `cookiesFile`: optional **absolute** path to a cookie file (no default).
- Never paste cookie contents into issues or chat. Review redacted `/export-diagnostics` bundles before sharing.
- Kunai does not bypass DRM or YouTube access controls; cookies only help yt-dlp with content your account can already play.

See [Providers → YouTube](/docs/users/providers#youtube).

### Provider relay

`providerRelay` is optional. Leave `baseUrl` empty for direct provider fetches
only. Set it when you run your own relay for provider metadata APIs that are
geo-blocked from your network.

```json
{
  "providerRelay": {
    "baseUrl": "https://your-relay.example",
    "token": "same-secret-as-the-relay-server",
    "fallbackToDirect": true,
    "providers": {
      "allanime": { "enabled": true }
    }
  }
}
```

Internet relay deployments require a bearer token configured on both the relay
server and Kunai. When an OS credential store (macOS Keychain, Windows
Credential Manager, or Linux Secret Service) is available, Kunai migrates
`providerRelay.token` and `youtubeMetadata.poToken` out of `config.json` into
the vault automatically. A token is optional only for the local development
server when it is bound to numeric loopback (`127.0.0.1` or `::1`).

`KUNAI_RELAY_BASE_URL` and `KUNAI_RELAY_TOKEN` override local config for smoke
tests and temporary sessions. The relay is metadata-only. Stream URLs always
stay direct, and unknown legacy video-relay keys are ignored.

### Language and media profiles

Kunai uses separate profiles for anime, series, movies, and YouTube:

During `kunai --setup`, the language screen also exposes a YouTube profile.
`Tab`/`Shift+Tab` cycle Shows, Movies, Anime, and YouTube; `←`/`→` switch
between audio and subtitles; `↑`/`↓` choose a value; and `a` copies the active
profile to all four lanes. Playback defaults (autoplay, intro skip, and credit
skip) start off. Press `s` for the recommended all-on defaults. The final setup
screen summarizes every choice before saving.

Example (not the shipped defaults; those use `audio: "original"` and `quality: "best"`):

```json
{
  "animeLanguageProfile": { "audio": "ja", "subtitle": "en", "quality": "1080p" },
  "seriesLanguageProfile": { "audio": "en", "subtitle": "en", "quality": "best" },
  "movieLanguageProfile": { "audio": "en", "subtitle": "en", "quality": "best" }
}
```

- `animeTitlePreference`: display English, romaji, native, or provider-native titles.
- `favoriteSources`: pin preferred source/server names to the top of pickers.

See [Media selection](/docs/users/media-selection) for how profiles flow into resolution and mpv.

### Playback and recovery

| Key | What it controls |
| --- | --- |
| `autoNext` | Autoplay next episode when available |
| `autoplayRecommendations` | YouTube-style continue into top recommendation when caught up |
| `skipIntro`, `skipRecap`, `skipPreview`, `skipCredits` | Auto-skip segments when timing metadata exists |
| `recoveryMode` | `guided`, `fallback-first`, or `manual` |
| `player` | Player when `--player` is not given: `auto` (default), `mpv`, or `vlc` (Android). Set it from Settings → Playback; applies on the next start |
| `resumeStartChoicePrompt` | Resume vs start-over overlay when resuming mid-episode |
| `quitNearEndBehavior` | What happens when you quit mpv near the natural end |
| `quitNearEndThresholdMode` | When "near the end" starts: `credits-or-90-percent` (default), or a fixed percentage |
| `continueSourcePreference` | Where Continue Watching resumes from: `auto` (default), `local`, `stream`, or `ask` |
| `prePlayConfirm` | Open the Tracks sheet before launch: `off` (default), `when-choices`, or `always` |

### Shell density, accessibility, and themes

| Key / flag | Effect |
| --- | --- |
| `plainMode` / `--plain` | Plain / screen-reader mode: no animation, no box art or decorative glyphs, linear single-column layout, text announcements for state and selection |
| `zenMode` / `--zen` | Single-column, minimal chrome; all features still key-reachable |
| `minimalMode` / `--minimal` | Collapse companion pane and dim header status |
| `footerHints` | `detailed` or `minimal` footer guidance |
| `discoverShowOnStartup` | Faint discover hint in browse footer when history exists |
| `discoverMode` | What `/discover` mixes: `auto` (default), `unified`, `anime-only` (anime series and films), or `series-only` |
| `discoverItemLimit` | Rows the Discover tray shows (default `24`) |
| `powerSaverMode` | Suppress background network and speculative work |
| `recommendationRailEnabled` | Show the recommendation rail after playback (default `true`) |

Kunai ships eleven themes: the **Ember Dusk** brand default, three accessibility-focused palettes (**Paper Sakura (Light)** `paper-sakura`, **High Contrast Dark** `high-contrast-dark`, and **High Contrast Light** `high-contrast-light`), plus seven dark alternates (**Kitsunebi**, **Nord**, **Tokyo Night**, **Catppuccin Mocha**, **Dracula**, **Rosé Pine**, and **Gruvbox**). Pick one with `/theme` or in **Settings › General › Theme** (it repaints immediately and persists), set `"theme"` in `config.json`, or override per run with `KUNAI_THEME=paper-sakura` or `KUNAI_THEME=high-contrast-dark`. `paper-sakura` meets WCAG AA (`>= 4.5:1`) and both high-contrast themes meet WCAG AAA (`>= 7:1`) for text and semantic status across every surface elevation. Themes recolor the whole shell; density modes (`plain`, `zen`, `minimal`) control chrome and layout.

### Motion, plain mode, and color overrides

These environment variables override preferences for one run without touching `config.json`:

| Variable | Effect |
| --- | --- |
| `KUNAI_PLAIN=1` (or `--plain`) | Enables plain / screen-reader mode for the run (no animation, no box art or decorative glyphs, linear layout, text state announcements). `KUNAI_PLAIN=0` forces it off even if `plainMode` is enabled in `config.json`. |
| `KUNAI_REDUCED_MOTION=1` or `NO_MOTION=1` | Stops every animated surface in the shell (petals, loaders, spinners, setup recheck, exit fade). Messages, progress, and timers stay readable without movement. `0` and `false` leave motion on. |
| `NO_COLOR=1` | Follows [no-color.org](https://no-color.org/): any non-empty value disables rich color and auto poster rendering; an empty `NO_COLOR=""` is ignored as unset. |
| `KUNAI_PET=glyph` or `KUNAI_PET=off` | Keep the Kanna companion as the `🦊` glyph only, or retire her entirely. See [Kanna](/docs/users/kanna). |
| `KUNAI_POSTER=0` | Turn off poster images. The glyph companion stays. |

### Downloads and offline

| Key | What it controls |
| --- | --- |
| `downloadsEnabled` | Gate for download features (off until opted in) |
| `downloadPath` | Custom download directory (empty = app data default) |
| `maxConcurrentDownloads` | Parallel download jobs (clamped 1–5) |
| `offlineFreeSpaceReserveBytes` | Reserved disk space before accepting new downloads |
| `defaultDownloadQuality` | Shared quality floor for new download jobs |
| `offlineMode` | Persistent local-only shell posture (separate from `--offline` launch) |
| `autoCleanupWatched` | Surface watched downloads as cleanup candidates |
| `autoCleanupGraceDays` | Days a watched download is kept before it becomes a cleanup candidate (default `7`) |
| `offlineArtworkCacheEnabled` | Cache poster artwork alongside downloads for offline browsing (default `true`) |

See [Downloads and offline](/docs/users/downloads-and-offline).

### Sync integrations (opt-in)

```json
{
  "sync": {
    "anilist": { "enabled": false, "trackWatched": false, "syncList": false },
    "tmdb": { "enabled": false, "trackWatched": false, "syncList": false }
  }
}
```

Tokens are stored separately. Sync is **experimental** and fail-closed: nothing leaves the machine until you connect an account in Settings › Accounts & Sync (or `/sync`, or during setup). Connecting turns that tracker's sync on, including episode progress (AniList) and lists; the switches above stay in your hands afterwards, and disconnecting turns it off. Pending mutations sit in a local **outbox** and retry; auth failure holds the row until you re-authenticate. Failed-closed rows do not invent progress on AniList/TMDB.

## Catalog sources and your own TMDB key

Search, trending, recommendations and the calendar come from public catalogs: TMDB for movies and series, AniList for anime.

- **Trending** has fallbacks: anime trending tries Kitsu and then MyAnimeList (Jikan) when AniList is down.
- **Trending and recommendations** remember their last good answer. If every source is unreachable, Kunai shows that list, marked with its age (`Trending this week · updated 3h ago`), instead of an empty row.
- **Series episode lists** keep working when TMDB is down for any series you have opened in the last 30 days: Kunai uses the season and episode list it saved last time, so you can still pick an episode. Release dates for series you follow use the same saved data.
- **Movie and series search** falls back to Wikidata when TMDB is unreachable. Results carry the same TMDB ids, so picking one plays the right title; they have no posters, and the header says `Wikidata (TMDB unreachable)`. Filtered searches (`type:`, `year:` and similar) still need TMDB.
- **Anime search** tries the other anime providers when the active one or AniList fails.
- **The calendar** keeps its series rows when TMDB is down, using TVmaze's US schedule matched to the same TMDB titles (the header says `series via TVmaze (TMDB unreachable)`; those rows have no episode numbers). The anime calendar needs AniList; when one part of the calendar cannot load, the header says which (`anime schedule unavailable`) instead of quietly showing less.
- **`/diagnostics`** has a "Catalog sources" line that says which source answered search, trending, recommendations and episode lists, and why a backup was used.
- **AniList limits requests.** When it asks Kunai to slow down, AniList-backed rows show their fallback or saved list for up to a couple of minutes instead of waiting.

### Your own TMDB key (free, recommended)

Kunai works without any key. Your own free TMDB key makes the catalog faster and keeps it working even if Kunai's key or the keyless mirrors have a bad day:

1. Sign in at [themoviedb.org](https://www.themoviedb.org/settings/api) and request an API key (personal use, free).
2. Copy either the **API Key** or the **API Read Access Token**.
3. Open **Settings → Accounts → Your API keys → TMDB key**, paste it, and press Enter.

With your key, Kunai asks TMDB directly first. The key is stored in your system's credential store (macOS Keychain, Windows Credential Manager, or Secret Service on Linux) when one is available, not in `config.json`. If TMDB ever rejects it, Kunai keeps working on its fallbacks and `/diagnostics` says so under **Service keys**.

`KUNAI_TMDB_API_KEY` in your environment overrides the setting, and is also the key TMDB account sync uses.

## Provider domains

Provider domains for the media (movie/TV and anime) providers are compiled in; changing a media-provider domain requires a code change and rebuild, not a config file. Exception: YouTube metadata endpoints are configurable via `youtubeMetadata.instanceUrl` and `youtubeMetadata.pipedApiUrl` in settings or `config.json`, no rebuild needed.

To reach provider metadata APIs through a different network, configure your own relay with `providerRelay.baseUrl` in `/settings` or `config.json`. See [Provider relay](#provider-relay). This changes the network path, not the provider domain; video stays direct.

## mpv flags and bridge options

Kunai always launches `mpv` for playback. You can forward diagnostic flags for a single run:

| Flag | Effect |
| --- | --- |
| `--mpv-debug` | Verbose mpv logging |
| `--mpv-clean` | Minimal mpv config for isolation testing |
| `--no-user-mpv-config` | Ignore user mpv.conf for this run |
| `--mpv-log-file <path>` | Write mpv log to a specific file |
| `--mpv-hwdec <mode>` | Override hardware decoding for one run (`auto`, `auto-safe`, `auto-copy`, `off`, or an explicit mpv decoder) |
| `--mpv-avsync-recovery <on\|off>` | Enable or disable sustained A/V-drift correction for one run |

These are process flags; see [CLI Reference](/docs/users/cli-reference#mpv-and-diagnostics).

### Persistent mpv bridge settings

For a desktop speed default, add `speed=1.25` to your own `mpv.conf`; remove it
or set `speed=1` to restore normal startup speed. Kunai reads mpv's user config
unless you use `--mpv-clean` or `--no-user-mpv-config`. Restart the player session
after editing it. In the player window, `[` / `]` adjust speed and `Backspace`
resets it for playback. This is an mpv preference, with locations documented in
the [mpv configuration reference](https://mpv.io/manual/master/#configuration-files).


Config keys tune the Kunai Lua bridge script:

| Key | Purpose |
| --- | --- |
| `mpvKunaiScriptPath` | Custom path to `kunai-bridge.lua` (empty = auto-resolve) |
| `mpvKunaiScriptOpts` | `--script-opts` entries for the bridge (e.g. `margin_bottom`, `chip_width`). An entry whose key or value contains `,` or `=` is dropped; mpv's option list cannot represent one |
| `mpvInProcessStreamReconnect` | Reload same URL after network-read-dead stalls |
| `mpvInProcessStreamReconnectMaxAttempts` | Max reload attempts per playback cycle (clamped 0–1; `0` disables reconnect) |
| `mpvHwdec` | Hardware decoding preference: `auto` (probe and use mpv's safe copy-back result), `auto-safe`, `auto-copy`, `off`, or an explicit mpv decoder such as `videotoolbox` |
| `mpvAvsyncRecovery` | Correct sustained audio/video drift in supervised persistent mpv playback (default `true`) |

Example `mpvKunaiScriptOpts`:

```json
{
  "mpvKunaiScriptOpts": {
    "margin_bottom": "130",
    "prompt_seconds": "8"
  }
}
```

Kunai still passes provider-required headers (referrer, user-agent) and subtitle attachments automatically. Do not expect arbitrary mpv CLI passthrough from config today; use the flags above for debugging.

## Discord presence setup

Discord Rich Presence is **off by default** and local-only.

<Steps>
<Step>
### Open presence settings

```text
/presence
```

Or use `/settings` and navigate to Accounts & Sync → Discord Presence.
</Step>
<Step>
### Choose provider and privacy

- Set **Presence** to `discord`.
- Set **Presence privacy** to `full` (title/episode detail) or `private` (generic activity).
</Step>
<Step>
### Discord desktop, then connect

The Discord **desktop app** must be running (local IPC). Kunai ships a default application client id; you do not need to create a Discord app for the default path. Override in Settings › Accounts & Sync or `KUNAI_DISCORD_CLIENT_ID` only if you want your own application. Presence stays **off** until you set the provider to `discord`.
</Step>
<Step>
### Connect and verify

Use **Connect Discord now** in Settings. Kunai connects through Discord's local IPC (Unix socket on Linux/macOS, named pipe on Windows), no cloud relay.

While playing, Kunai updates episode cards and progress timestamps. Paused playback shows static text; activity clears after a configurable idle delay.
</Step>
</Steps>

Diagnostics record presence connect/clear failures. Check `/diagnostics` if Discord shows `unavailable` or `error`.

More: [Diagnostics and reporting](/docs/users/diagnostics-and-reporting).

## Editing config safely

<Tabs items={["In-shell", "Manual edit"]}>
<Tab value="In-shell">

Use `/settings` or `/setup` for guided changes. Settings persist immediately to `config.json`.

</Tab>
<Tab value="Manual edit">

1. Quit Kunai (or edit while idle; avoid editing mid-playback).
2. Edit `~/.config/kunai/config.json` with valid JSON.
3. Restart Kunai. Invalid JSON falls back to defaults with a stderr warning.

</Tab>
</Tabs>

<Callout type="idea" title="Reset without uninstall">
Delete `config.json` to reset preferences. Use `kunai uninstall --purge` only when you want config, history, cache, and default downloaded videos removed together (Linux: `~/.local/share/kunai/downloads`, or `$XDG_DATA_HOME/kunai/downloads`). Custom/external download directories outside Kunai's config, data, and cache directories are preserved. See [Install and update](/docs/users/install-and-update#lifecycle-cli-only) for all platform paths.
</Callout>
