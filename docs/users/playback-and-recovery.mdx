Kunai keeps playback centered on one shell session. After `mpv` exits, you return to Kunai with browse context, history, and recovery tools intact.

This guide covers the full playback lifecycle, from first resolve through recovery when providers or networks misbehave.

## Desktop VLC

`kunai --player vlc` plays in VLC instead of mpv, keeping your VLC interface,
hotkeys and settings. With the default `--player auto`, Kunai also uses VLC when
it is installed and mpv is not, so a first play works without installing
anything. Kunai talks to VLC through a private control interface on
`127.0.0.1` (its password is never on the command line), so VLC playback still
gets:

- resume from your last position, watch history, Continue Watching and
  tracker sync;
- completion and the next episode, startup-stall and "video isn't decoding"
  recovery to another source;
- auto-skip of intros, recaps and credits (the same toggles as mpv, and the
  skip key for a segment you are in), by seeking past them;
- autoplay in one window: the next episode opens in the VLC window you are
  already watching instead of a new one;
- provider streams that need special headers, through Kunai's local stream
  gateway, and external subtitles;
- downloaded episodes offline.

Not yet in VLC: an on-screen "Skip intro" prompt (VLC skips without one),
Kunai's in-player menu and share key, switching audio or subtitle tracks from
Kunai's Tracks panel, and streams that need yt-dlp (YouTube). Use
`--player mpv` for those. On Linux, install VLC's ffmpeg decoder too (`vlc-plugin-ffmpeg` on Arch);
without it VLC plays the sound but no picture, which Kunai now reports instead
of calling it playback.

## Android external-player preview

Inside Termux, `--player auto|vlc|mpv` hands a qualified direct stream to the
Android chooser, VLC, or mpv-android. Kunai returns to a dedicated “opened
externally” state as soon as Android accepts the intent. That does **not** prove
the media started or finished.

Detached playback therefore has deliberately smaller behavior:

- no automatic progress, completion, watched-state, or provider-health inference;
- no autoplay, auto-skip, near-EOF prefetch, or in-terminal player controls;
- a claimed queue item returns to pending instead of being marked played;
- offline/local files, external subtitles, yt-dlp-dependent playback, and
  streams requiring headers or cookies are rejected before launch.

Use desktop mpv or VLC when you need full history/resume, subtitle attachment,
recovery, or autoplay parity. iOS is not implemented.

## Resume and continue

Local watch history drives resume. Nothing leaves your machine unless you opt into sync.

| Entry                     | Behavior                                                                          |
| ------------------------- | --------------------------------------------------------------------------------- |
| `--continue` / `--resume` | Newest unfinished history entry                                                   |
| `--history`               | Manual pick from watch history                                                    |
| `/history`                | Same from inside the shell                                                        |
| Resume overlay            | When `resumeStartChoicePrompt` is on, choose resume vs start over before seek     |
| Shared link timestamp     | `kunai://` `t=` applies once on first mpv launch, then per-episode history resume |

The overlay itself is mpv's persistent autoplay session. Player paths that cannot show it (desktop VLC and one-shot mpv when Autoplay next is off) honor the same resume offer by opening at the saved position while `resumeStartChoicePrompt` is on. An explicit restart, replay, quality pick, or share-link timestamp still wins and starts where you asked.

Episode numbers in the UI are **1-based**. Providers adapt internally.

More: [Continue watching and new episodes](/docs/users/continue-watching-and-new-episodes), [Share links](/docs/users/share-links).

## Keys in the mpv window

The mpv window uses the same keys as `?` help in the terminal: `o` source,
`k` quality, `e` episode, `s` reload subtitles, `⇧S` back to search, `a`
autoplay, `u` autoskip, `x` stop after this episode, `m` title menu, `d`
diagnostics, `⇧F` fallback, `n`/`p` next and previous, `b` skip. Three keys
exist only in the mpv window: `c` cycles to the next source, `⇧A` cycles audio
or sub/dub, and `Ctrl+⇧S` copies a share link at the current moment. mpv's own
`v` (subtitle visibility) is left alone.

When the resume card appears, click it (or press Enter) to resume; right-click
or Esc keeps playing from where it loaded.

## Recovery commands

Provider catalogs drift. Recovery is normal usage.

| Action                  | Keys / command                                            | Effect                                                 |
| ----------------------- | --------------------------------------------------------- | ------------------------------------------------------ |
| Recover stream          | `r` in the recovery prompt or during playback, `/recover` | Refresh current provider intent                        |
| Refresh stream (in mpv) | `Ctrl+R`                                                  | Re-resolve the same episode without leaving playback   |
| Resume saved position   | `Alt+R`                                                   | Jump back to your last position after refresh          |
| Fallback provider       | `⇧F`, `/fallback`                                         | Next compatible provider                               |
| Recompute               | `/recompute`                                              | Bypass stale cache for current episode                 |
| Replay                  | `/replay`                                                 | Start current episode from beginning                   |
| Source                  | `o`, `/source`                                            | Switch source / mirror                                 |
| Quality                 | `k`, `/quality`                                           | Switch quality                                         |
| Reset provider health   | `/reset-provider-health`                                  | Forget down-provider memory so auto-fallback can retry |
| Clear cache             | `/clear-cache`                                            | Drop cached stream URLs                                |
| Diagnostics             | `/diagnostics`                                            | Runtime panel with attempt timeline                    |
| Export                  | `/export-diagnostics`                                     | Redacted support bundle                                |

<Callout type="idea" title="Try recover before fallback">
  Recover keeps the same provider and may reload mpv or re-resolve. Fallback switches providers and
  may change quality or subtitles.
</Callout>

### Recovery mode

Configure in `/settings` or `config.json`:

- **guided** (default): explain failures; suggest recover then fallback
- **fallback-first:** move to next provider sooner after classified failures
- **manual:** you drive `/recover` and `/fallback`. Kunai may still try the
  provider's other sources, but never moves to another provider on its own

See [Customization](/docs/users/customization) and [Providers](/docs/users/providers).

## Hardware decoding and sync recovery

On desktop mpv, `mpvHwdec` controls hardware video decoding. The default
`mpv-default` passes no `--hwdec` override, so mpv.conf and mpv's own defaults
keep control. Choosing `auto` uses a small bounded probe, cached for seven
days, as evidence that mpv can open a hardware decode path. A successful cache
entry makes the next mpv process pass `--hwdec=auto-safe`; mpv then chooses the
backend with the real video output at playback time. On a cache miss playback
starts immediately with mpv's own behavior while the probe warms in the
background for the next mpv process start. Discovery is OS-aware on Linux,
macOS, and Windows; explicit mpv decoder names are also accepted. `auto-safe` and
`auto-copy` use mpv's automatic modes directly, and `off` forces software
decoding. If mpv is missing, the probe cannot run, or no GPU path proves
usable, `auto` playback falls back to mpv's own default rather than failing.
Settings → Playback, `config.json`, or `--mpv-hwdec` can change or disable the
behavior. Changes apply when an mpv process starts; an already-running
persistent mpv process keeps its launch-time mode.

Supervised persistent playback also watches mpv's audio/video drift. Brief
drift is left to mpv, but drift larger than about 0.3 seconds sustained across
several samples can trigger one corrective seek at the current position after
playback has started. It does not run while you pause or seek, while cache is
stalled or the decoder is idle, during reconnects or Kunai-issued resume seeks,
before video output starts, or for live streams. Corrections cool down for five
seconds, repeated immediate drift gives up instead of seek-looping, and an
episode is limited to two corrections. Set `mpvAvsyncRecovery` to `false` or use
`--mpv-avsync-recovery off` to turn it off.

## Autoplay and auto-skip

| Setting                   | Effect                                                |
| ------------------------- | ----------------------------------------------------- |
| `autoNext`                | Advance to next released episode when current ends    |
| `autoplayRecommendations` | When caught up, countdown into top recommendation     |
| `skipIntro`               | Auto-skip intros when timing exists (**default on**)  |
| `skipCredits`             | Auto-skip credits when timing exists (**default on**) |
| `skipRecap`               | Auto-skip recaps (**default off**)                    |
| `skipPreview`             | Auto-skip previews (**default off**)                  |
| `/toggle-autoplay`        | Toggle autoplay for current session                   |
| `/toggle-autoskip`        | Toggle auto-skip for current session                  |
| `/stop-after-current`     | Finish current episode then stop chain                |

Autoskip needs IntroDB (TMDB-keyed) and/or AniSkip (MAL-keyed, anime mode). Not every title has timing. Episode numbers in the UI are **1-based**; providers adapt internally.

AniSkip for split-cour anime: when the only MAL mapping is TMDB season-1, Kunai **skips AniSkip for season 2+** rather than applying the wrong show's windows. Miruro is keyed on AniList, where each cour is its own entry with its own MAL id, so that gap does not arise there; AniDB stamps MAL at resolve when it can.

## Audio and subtitles

- Language profiles differ for anime, series, and movies (`animeLanguageProfile`, etc.).
- Kunai passes preferred subtitle first when launching mpv.
- Additional subtitle tracks attach when available; switch inside mpv without another lookup.
- Press `s` during playback to reload subtitles.
- Late subtitle search uses Wyzie only when you set your Wyzie key in Settings › General. Kunai ships no key. Like the TMDB key, it is kept in your system's credential store when one is available.
- Source/quality/language variants prefer cached stream inventory to avoid extra network calls.

Use `/source` or `/tracks` during playback for the grouped media panel.

## mpv supervision

Kunai monitors mpv through IPC and the Kunai bridge Lua script:

- Progress reporting for history and Discord presence
- In-process stream reconnect after network-read-dead stalls (configurable).
  A link the server refuses outright (403, 404, unreachable) or that holds no
  playable video is not retried; Kunai moves to the next source instead.
- A source that has sent nothing at all in 15 seconds is treated as dead and
  skipped. A slow source that is still sending gets the full 45 seconds to start.
- A stream that dies mid-episode (no data arriving, or the picture stops while
  the clock runs) first gets one reload of the same link. If that does not
  bring it back, Kunai moves to the next source and continues from the same
  moment, in the same window, without asking where to resume. When the
  provider's sources are used up it moves to another provider the same way,
  except in `manual` recovery mode. This works with mpv and desktop VLC; local
  files have no other source and Android hands playback off to another app.
- A source that fails before reaching your resume point never restarts the
  episode from 0:00; the next source still starts where you were.
- Auto-skip overlay when timing metadata and autoskip are enabled

When playback recovers on its own (buffering clears, a stall resolves, or a
seek completes), the shell returns to playing as soon as fresh progress arrives,
so a transient hiccup no longer leaves the header stuck on "buffering" for the
rest of the episode. Recovery never overrides a deliberate state: pausing,
stopping, or finishing stays exactly as you left it, and only resuming restarts
playback. Diagnostics keep the record of the stall or the source switch even
after playback looks healthy again, so `/diagnostics` can still explain what
happened mid-episode.

Starting a new episode or stopping playback retires the old mpv session
immediately. Late events from that retired session are discarded rather than
applied, so a replaced episode cannot be revived by the previous one's activity.

Debug mpv for one run:

```sh
kunai --mpv-debug --mpv-log-file /tmp/kunai-mpv.log -S "Title"
```

See [CLI Reference](/docs/users/cli-reference#mpv-and-diagnostics).

## Post-playback behavior

When mpv exits:

- **Near end:** `quitNearEndBehavior` controls whether autoplay may still advance
- **Autoplay chain:** next episode resolves automatically when enabled
- **Recommendation rail:** optional compact suggestions after series completion
- **History write:** position and watched state persist locally

Queue recovery: if a previous session crashed with pending queue items, Kunai may show a recoverable queue notice. Restoring moves items into the current session without autoplaying them.

## When playback fails

1. Open `/diagnostics`: read provider timeline and mpv/player section.
2. Press `r` to recover.
3. Press `⇧F` if recover loops or failure class suggests provider exhaustion.
4. Export evidence: `/export-diagnostics`.

Symptom-specific steps: [Troubleshooting](/docs/users/troubleshooting).

## HDR and 4K playback

Kunai detects `HDR10` (`VIDEO-RANGE=PQ`), `HLG`, and Dolby Vision (`dvh1`/`dvhe`) streams from HLS master playlists and labels them in the Tracks picker (`2160p HDR10`, `2160p DV`). When a playlist mixes SDR and HDR rungs, the label shows the strongest range present; `mpv` still picks the rung it plays.

Configure **HDR playback** in `/settings` (Playback) or override it for a single run with `--hdr`:

| Mode             | Effect                                                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `auto` (default) | Kunai adds no HDR options. `mpv` and your `mpv.conf` decide; by default `mpv` tone-maps HDR to SDR.                                    |
| `passthrough`    | For HDR displays: `--vo=gpu-next --target-colorspace-hint=yes`. When you pick a source, prefers the HDR variant at equal quality.      |
| `tone-map`       | Forces SDR output: an SDR target (`--target-prim=bt.709 --target-trc=bt.1886`) that overrides `mpv.conf`, tone-mapped with `bt.2446a`. |
| `sdr-only`       | Same output as `tone-map`. When you pick a source, also prefers the SDR variant at equal quality; a higher-resolution HDR stream wins. |

The explicit modes use `gpu-next` options (`mpv` 0.35 or newer, built with libplacebo). Kunai checks `mpv --vo=help` before the first launch that needs it and remembers a successful answer for the session. Without `gpu-next`, older `mpv` builds still start: `passthrough` sends only `--hdr-compute-peak=yes`, and the SDR modes send the SDR target and `--hdr-compute-peak=yes`, leaving tone-mapping to `mpv`'s default. During an autoplay chain the running `mpv` keeps the mode it started with; a change applies the next time `mpv` starts.

When your `mpv` has no `gpu-next`, Kunai says so instead of degrading silently: `passthrough` shows that it is playing as SDR, and a Dolby Vision stream warns that colours may look wrong (Dolby Vision needs libplacebo; profile 5 shows purple and green without it). Detection covers Dolby Vision on HEVC, AV1 and AVC.

```sh
kunai --hdr passthrough -S "Dune"
kunai --hdr tone-map -S "Dune"
```

## Offline playback

Completed downloads play through the same mpv path with local file URLs:

```sh
kunai --offline
/library
```

Offline playback writes history with the same shape as online. Opening the offline library never calls providers.

More: [Downloads and offline](/docs/users/downloads-and-offline).
