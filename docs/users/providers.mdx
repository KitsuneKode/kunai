Kunai resolves playable streams through direct HTTP provider adapters. You pick a title; Kunai asks registered providers for stream inventory; playback goes to mpv or VLC.

This page explains **user-visible provider behavior**. It does not document scraper internals, crypto constants, or site-specific extraction logic.

<ProviderDocSection id="youtube" title="YouTube">

**Adapter role:** YouTube mode: Invidious search, yt-dlp stream handoff to the selected player. This is not a TMDB movie/series adapter.

**Config id:** `youtube`. Switch with `/youtube-mode` or `Tab` to cycle catalog mode.

**Caveats:** requires network; yt-dlp must be available for resolve. Kunai does **not** bypass DRM or circumvent YouTube access controls. It only forwards optional cookies you already have to yt-dlp/mpv.

Search can return **videos, Shorts, playlists, and channels**. Results retain
their shape and the shell labels it before playback, so a Short is not mistaken
for a collection. Playlists and channels are catalog collections
(`youtube-playlist:…` / channel ids): pick a video inside them to play. Live
and upcoming entries carry their own status badge (`● LIVE` for an active
broadcast, `Upcoming` for a premiere that has not started, `Was Live` for an
archived stream). Backends that omit a shape or status signal are labelled
conservatively. Use `type:short` in YouTube search to narrow to Shorts; that query
runs YouTube's own Shorts search through yt-dlp rather than filtering ordinary
results, which never include Shorts. If it finds none, it says so instead of
falling back to regular videos.

Live URLs (`youtube.com/live/…`) resolve as videos. Kunai passes
`--no-live-from-start` to yt-dlp so a live handoff joins at the live edge, and it
will not offer to resume a broadcast from a saved position; a live stream has no
fixed position to return to. Opening a premiere that has not started tells you so
instead of handing mpv a stream that cannot play yet.

**SponsorBlock** is off unless you set `youtubeMetadata.sponsorblockRemove` in Settings › Sources › YouTube (for example `sponsor,intro`). That value is forwarded to yt-dlp / mpv. There is no shipped default category list.

Forwarding SponsorBlock options does not establish that segment removal works
during streaming. Kunai makes no ad-free or Premium-equivalent playback promise.

Quality choices preserve yt-dlp's discovered format IDs. Codec, frame rate and
average bitrate appear when reported; two rows at the same resolution can be
different formats. Bitrate is reported metadata, not measured connection speed.
Primary/fallback connections are extractor methods for the same video. Picking
a quality keeps the current connection when it has that format. Exact video
formats do not silently fall back to a different video format; availability is
still checked by mpv. Video-only formats use yt-dlp's best audio choice.

### Cookie safety (age-restricted / members)

Optional keys under `youtubeMetadata` in `~/.config/kunai/config.json` (also editable from `/settings` → Sources → YouTube):

| Key                  | Safe usage                                                                                                                                                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `cookiesFromBrowser` | Browser name for yt-dlp `--cookies-from-browser` (for example `chrome`, `firefox`). Reads cookies from that browser profile on your machine.                                                           |
| `cookiesFile`        | **Absolute** path to a Netscape cookie file passed as yt-dlp `--cookies`. Relative paths are easy to mis-resolve; use an absolute path.                                                                |
| `poToken`            | Proof of Origin token in yt-dlp's `CLIENT.CONTEXT+TOKEN` form (for example `visionos.gvs+...`). A bare token is scoped to whichever client Kunai is asking for. Used for playback and downloads alike. |

Safety rules:

- Never paste cookie file contents into issues, chats, or support bundles.
- Prefer `cookiesFromBrowser` when it works; keep `cookiesFile` private on disk.
- Before sharing `/export-diagnostics` or `/report-issue` output, open the redacted bundle locally and confirm cookies/tokens/paths stay redacted.
- There is no shipped default cookie file and no claim of DRM bypass.

## How resolution works (user view)

<Steps>
<Step>
### You select a title and episode

Kunai builds a resolve request from your mode, language profiles, and any per-title provider preference.

</Step>
<Step>
### Kunai tries the default provider first

Your `provider` or `animeProvider` config key sets the session default. Startup priority policy may influence first pick.

Two exceptions, both shown on the loading line:

- If your provider failed on this title before and another one worked, Kunai starts with the one that worked, then tries yours.
- If your provider is currently down (repeated failures), Kunai tries it last instead of first.

Neither applies right after you pick a provider yourself, after `/recompute`, or in the **Ask before switching** recovery mode: then your choice always goes first.

Falling back to another provider can change the available source inventory (quality ladder, sub/dub
mix). Title and catalog identity never silently cross to another catalog: an advanced search with no
compatible catalog is reported as unsupported rather than quietly answered by TMDB.

</Step>
<Step>
### Provider-local cycling

Within one provider, Kunai may try multiple sources, servers, or variants before giving up. Diagnostics shows this as retry progress, not necessarily an error.

</Step>
<Step>
### Global fallback

If the active provider is exhausted, skipped, or unhealthy for this request, Kunai moves to the next id in your priority list.

</Step>
<Step>
### Stream handoff

The winning stream becomes input for the selected player with required headers and subtitle attachments. Inventory is cached for faster re-selection.

</Step>
</Steps>

More detail on pickers: [Media selection](/docs/users/media-selection).

## Fallback chain configuration

Configure order in `/settings` or `~/.config/kunai/config.json`:

```json
{
  "provider": "vidlink",
  "providerPriority": ["movy", "rivestream", "vidrock", "videasy"],
  "animeProvider": "hianime",
  "animeProviderPriority": ["kickassanime", "animegg", "miruro", "allanime"]
}
```

The anime client shows as **AllManga** in the UI; the config id remains `allanime`. Every
registered anime provider is tried automatically when the selected one fails. The priority list
sets the order, it does not decide who is included.

On the first launch after updating, Kunai upgrades a saved anime order if the provider and
priority list exactly match the defaults for that configuration's revision. Custom orders are
preserved. A saved AniDB selection maps to HiAnime, and retired AniDB entries are removed.

Rules:

- Empty priority arrays use registry default order.
- Unknown ids in the list are ignored.
- Providers not listed remain available **after** configured entries.
- Per-title overrides in `titleProviderPreferences` win over history provider on resume.

See [Customization](/docs/users/customization).

## Retry vs recover vs fallback

Kunai uses three distinct user-facing actions. They are not interchangeable.

| Action                | Keys / command    | What happens                                                                                               |
| --------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------- |
| **Recover**           | `r`, `/recover`   | Refresh current playback intent on the **active** provider: new resolve, cache revalidation, or mpv reload |
| **Retry** (automatic) | none              | Provider-local cycling through sources/variants before global fallback; shown in diagnostics timeline      |
| **Fallback provider** | `⇧F`, `/fallback` | Stop active provider; global engine picks **next compatible provider**                                     |
| **Recompute**         | `/recompute`      | Bypass stream cache and provider health memory for current episode                                         |

<Callout type="idea" title="Recover before fallback">
  When a stream dies mid-playback, try recover first. Fallback switches providers and may change
  source quality or subtitles.
</Callout>

### Recovery mode setting

`recoveryMode` in config changes default aggressiveness:

| Mode               | Behavior                                                           |
| ------------------ | ------------------------------------------------------------------ |
| `guided` (default) | Explain failures; suggest recover then fallback                    |
| `fallback-first`   | Prefer moving to next provider sooner after classified failures    |
| `manual`           | Minimal automatic fallback; user drives `/recover` and `/fallback` |

## Provider health and cache

Kunai remembers provider health locally to avoid hammering known-bad paths. Health updates come from resolve outcomes, not from your home network being offline.

- **Cache hit:** reuse recent stream inventory when still valid.
- **Stale cache:** revalidate before play when health checks fail.
- **Cold resolve:** full provider lookup when no usable cache exists.

`/diagnostics` shows cache provenance and health deltas without exposing signed URLs.

Network-unavailable failures stop cycling early. Kunai does not mark unrelated providers as unhealthy because your Wi-Fi dropped.

## Domain overrides

Provider domains for the media (movie/TV and anime) providers are compiled in; changing a media-provider domain requires a code change and rebuild, not a config file. Exception: YouTube metadata endpoints are configurable via `youtubeMetadata.instanceUrl` and `youtubeMetadata.pipedApiUrl` in settings or `config.json`, no rebuild needed. To use a different network path for metadata calls, set `providerRelay.baseUrl` in `/settings` or `config.json` to your own relay; see [Provider geo relay](#provider-geo-relay).

## Provider geo relay

Some provider metadata APIs are geo-blocked from some countries while the final
video CDN still works globally. Kunai supports an optional **user-owned**
provider relay for those metadata calls.

What it does:

- Routes provider API/search/source JSON through your relay when
  `providerRelay.baseUrl` is set.
- Keeps playback direct: mpv receives the final stream URL and fetches it from
  your network.
- Uses provider manifest allowlists, so it is not an arbitrary URL proxy.

What it does not do:

- Kunai does not operate a public relay for you.
- Kunai does not host or proxy video. There is no video-relay configuration; stream URLs always stay direct.
- The relay does not bypass provider login or DRM.

Installed binaries: leave `providerRelay.baseUrl` empty (the default) for direct fetches. To use a relay you operate, set `baseUrl` in `/settings` or `config.json` to **your** origin; Kunai never ships a public relay URL. An internet relay requires a matching bearer `token`; only a relay bound to numeric loopback may run without one. `fallbackToDirect: true` degrades to direct fetches after relay network or authorization-policy failures where the provider is not geo-blocked. Env overrides: `KUNAI_RELAY_BASE_URL`, `KUNAI_RELAY_TOKEN`.

### Deploying your own relay

A relay requires a network from which the provider accepts metadata requests. If the provider
asks for a CAPTCHA or denies access, choose another provider. Both deployment options use a
source checkout because the relay imports the `@kunai/relay` and `@kunai/providers` workspace packages.

**On Vercel.** Full steps and the reason handler bundling is required are in `apps/relay-server/README.md`:

```sh
cd apps/relay-server
vercel env add RELAY_TOKEN   # a random secret; the relay refuses internet traffic without one
vercel build --prod --yes
vercel deploy --prebuilt --prod
```

**Locally**, for development or a home server on an ungated network:

```sh
bun run dev:relay            # listens on http://127.0.0.1:8787
```

### Pointing Kunai at your relay

Set the origin and token in any one of three places (`/settings` → Sources → Provider relay, `config.json`, or the environment) and keep `fallbackToDirect` on so Kunai degrades to direct fetches when the relay is unreachable and the provider is not geo-blocked.

```json
{
  "providerRelay": {
    "baseUrl": "https://your-relay.vercel.app",
    "token": "your-secret-token",
    "fallbackToDirect": true
  }
}
```

Environment overrides: `KUNAI_RELAY_BASE_URL`, `KUNAI_RELAY_TOKEN`. Leave the token blank only for a relay bound to numeric loopback; any internet origin needs one.

Source-checkout smoke and verification steps: [Debugging workflow](/docs/developer/debugging-workflow) and `apps/relay-server/README.md`.

## When your network blocks provider sites

Some internet providers answer DNS lookups for streaming sites with a dead
address, so a provider looks broken even though it works everywhere else.
Kunai looks up provider site names through DNS-over-HTTPS (Cloudflare,
`1.1.1.1`) to get past that, and falls back to your normal DNS when Cloudflare
cannot be reached.

- Video is still looked up with your normal DNS, the same way your player does,
  so Kunai never approves a stream your player cannot open.
- Local addresses (`localhost`, `*.lan`, `*.local`, IP addresses) and requests
  that go through an `HTTPS_PROXY` are never sent to Cloudflare.
- Turn it off in **Settings › Sources › DNS-over-HTTPS**, or launch with
  `KUNAI_DOH_DISABLE=1`.

## Stremio addons

Stremio addons are experimental and off by default. Kunai ships none. Enable them in Settings → Sources → Experimental: Stremio addons or run kunai addons enable.

> Stremio addons are third-party servers you choose. Kunai checks each addon stream, but mpv opens its own connection. A hostile addon server could answer mpv differently and reach a device on your network. Older FFmpeg versions may follow redirects. Downloads and Android handoff do not use addons.

Only install addons you trust.

```sh
kunai addons enable
kunai addons add https://example-addon.com/manifest.json
kunai addons list
kunai addons check
kunai addons disable
kunai addons remove 1
```

`kunai addons enable` asks you to confirm when standard input, output, and error are attached to a terminal. An empty answer or closed input declines. Kunai shows the warning the first time and remembers your acknowledgement across disable and re-enable. In a script or CI job, run `kunai addons enable --accept-risk` to accept without a prompt. An interactive `add` can ask you to enable addons in the same step. A non-interactive `add` while addons are off refuses before contacting the addon: run `kunai addons enable` first.

If the URL carries an account token, prefer `--stdin` so it stays out of your
shell's process list and history. Kunai reads one line of standard input;
paste it there, or redirect a file:

```sh
kunai addons add --stdin < addon-url.txt
```

You can also add and remove addons in **Settings → Sources → Stremio addons**, and turn the whole feature on or off under **Experimental: Stremio addons** there.

- **On and off.** `kunai addons disable` stops addon use at the next resolve, including in a session that is already running, and keeps your installed list and preferences. `kunai addons enable` turns them back on; addons that were already loaded can answer again at the next resolve. A Kunai session that started while addons were off never loaded them, so restart that session to use addons, and restart any session to pick up newly installed addons. `kunai addons list` and `kunai addons check` still work while off: they report the disabled state, and `check` does not contact the addon.
- **What to paste.** The addon's `https://…/manifest.json` address. A `stremio://…/manifest.json` link is the same address and works too. If the addon has a configure page, finish that first and paste the URL it gives you.
- **Where it sits.** A new addon goes after your other movie and series providers, so it is asked only when the ones before it have nothing. Move it up in **Settings → Sources → Provider priority**, or pause it with its provider switch.
- **When it applies.** Adding takes effect the next time Kunai starts. Removing inside the app applies on the next title; `kunai addons remove` asks already-running sessions to restart first. Remove deletes the entry; disable keeps it and stops addon use instead.
- **What plays.** Only direct video files: MP4-family and WebM/Matroska. Kunai's probe refuses playlists (HLS, DASH) and redirects, and Kunai re-checks the link with a small ranged request immediately before handing it to `mpv`; that check confirms the file answers, not that it plays in mpv end to end. Kunai has no torrent client, so torrent-only results are skipped, and Kunai tells you when that is all an addon offered. Subtitles an addon offers get the same treatment: they are downloaded through a guarded, size-limited request and must prove they are really WebVTT, SRT, or ASS text (anything else is skipped), and mpv only ever sees the local copy, never the remote URL.
- **Desktop mpv only.** Addon streams do not support Android player handoff or downloads: no addon candidate participates in a download, the cached-stream and enqueue guards stay in place, and a playback fallback that lands on an addon is refused there too. To download the title, choose a built-in provider.
- **Which titles.** Movies and series that have an IMDb id. Addons are not used in anime mode.

**Treat the URL like a password.** A configured addon keeps your settings, and sometimes an account token, in its URL. Kunai shows a configured addon only as `addon @ host`, never the full URL or its reported name and version, and keeps it out of logs and diagnostics. It is stored in your `config.json`.

**An addon is a third-party server you chose.** Kunai sends it the IMDb id of what you are about to watch. It accepts only JSON from it, runs nothing it sends, and checks that a link answers before handing it to `mpv`; that check confirms the link responds, not that it plays in mpv end to end. mpv opens a separate connection and looks up the host again, so this is not a network sandbox. mpv builds linked against older FFmpeg may still follow an HTTP redirect during playback, even though Kunai's probe refuses it.

## When providers fail (expected behavior)

Provider catalogs drift. Failure is operational, not exceptional.

1. Diagnostics records failure class and stage.
2. Kunai attempts provider-local retries when inventory exists.
3. Global fallback runs when configured and appropriate.
4. You stay in the shell with context intact; search, history, and offline library remain available.

If **all** providers fail, Kunai explains why in diagnostics and the shell footer. Collect evidence with `/export-diagnostics`; see [Troubleshooting](/docs/users/troubleshooting).

## What Kunai does not do with providers

- No browser/Playwright scraping in the active beta runtime
- No Kunai-hosted proxy or stream relay; the optional provider geo relay is user-owned and metadata-only by default
- No guarantee of subtitle language, quality tier, or dub availability
- No silent provider switching without user action (except configured automatic fallback within policy)
- No bundled Stremio addons and no torrent playback; an addon you add yourself can only supply direct video links

See [Supported and Unsupported](/docs/users/supported-and-unsupported).

## Picking a provider manually

Before playback starts:

- Provider picker in the starting-episode flow when multiple providers are compatible.
- `/source` or `/tracks` during playback when inventory supports switching without full re-resolve.

After explicit pick, Kunai stores per-title preference for future resume.

That preference is where the next resolve starts, not a lock. If the picked provider fails for an
episode, **Settings → Recovery mode** set to **Balanced recovery** or **Fast fallback** still hands
you a working stream from another provider. Only **Ask before switching** (or `/recompute`) keeps
the request to exactly the provider you picked.
